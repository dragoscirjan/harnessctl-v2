# HTML

- Use native semantic elements and controls before ARIA. Add ARIA only when native semantics cannot express the behavior.
- Preserve the repository's accessibility target; verify keyboard operation, labels, focus order, headings, landmarks, alternative text, and error communication for changed UI.
- Maintain supported-browser and rendering constraints. Do not hard-code a newer HTML or WCAG target over explicit project policy.
- Keep structure meaningful without presentation-only markup. Coordinate visual concerns with the selected CSS approach.
- Use configured validators, formatters, accessibility checks, and UI tests; named standards do not authorize new tooling.
