# Markdown

- Follow repository documentation style, dialect, renderer, line-wrapping policy, and local lint configuration.
- Keep headings hierarchical, links descriptive, examples accurate, and code fences language-tagged when known.
- Preserve generated sections and tool-specific frontmatter. Do not reflow tables or prose when it creates unrelated churn.
- Validate links, snippets, and generated documentation with existing project commands when applicable.
- Use configured formatters or Markdown linters; do not assume Prettier or ESLint is installed. Code-oriented class and architecture rules do not apply.
