# Docs

Choose a route based on what you need to accomplish. New users can reach a controlled
first result through Installation and Getting Started; the remaining guides explain one
area without duplicating its canonical reference.

## Start a workflow

1. [Installation](installation.md) prepares a supported coding harness in a project.
2. [Getting Started](getting-started.md) runs Plan and ends at the first approved Epic
   plan.
3. [Command Reference](command-reference.md) explains the installed commands and their
   stopping points.

Read [Introduction to SDLC](sdlc-introduction.md) for lifecycle fundamentals or
[Harnessctl SDLC](sdlc.md) for Harnessctl's approval, checkpoint, and phase boundaries.

## Choose a content type

- **Tutorials** lead through a complete outcome in order. Start with
  [Getting Started](getting-started.md).
- **Explanatory guides** build understanding and support decisions. Use
  [Introduction to SDLC](sdlc-introduction.md) for the lifecycle model and
  [Harnessctl SDLC](sdlc.md) for its controlled execution rules.
- **Catalogs** inventory available integrations and capabilities. Browse
  [Harnesses](harnesses.md), [Skills](skills.md), or [MCP Servers](mcp-servers.md).
- **Exact references** provide precise command and field details. Use the
  [Command Reference](command-reference.md) or [Config Schema](config-schema.md).
- **Troubleshooting and help** answer failures and common questions. Go to
  [Troubleshooting](troubleshooting.md) or the [FAQ](faq.md).

## Configure the system

- [Configuration](configuration.md) explains overlays and current settings.
- [Config Schema](config-schema.md) is the field-level reference.
- [Harnesses](harnesses.md) records host support and installed locations.
- [Skills](skills.md) catalogs the guidance available to each workflow.
- [MCP Servers](mcp-servers.md) describes external tool connections.

## Work with project authority

- [Issues](issues.md), [Documents](documents.md), and [Memory](memory.md) explain the
  repository-backed records used by lifecycle commands.
- [CVS and MCP Providers](cvs.md) covers local version control, remote providers, and
  consent boundaries.
- [Code Intelligence](code-intelligence.md) and
  [External Providers](code-intelligence-providers.md) cover optional retrieval evidence.

## Diagnose or confirm behavior

- [Troubleshooting](troubleshooting.md) and [FAQ](faq.md) address known problems and
  common questions.
- [Feature Status and Evidence](status-and-evidence.md) explains how support claims are
  qualified.
- [Changelog](changelog.md) records user-visible changes.
